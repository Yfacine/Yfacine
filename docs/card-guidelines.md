# 프로필 카드 제작 및 배치 기준

**기준 버전: v0.1** — 프로필 카드와 각 저장소 README 표지에 공통 적용한다.

이 문서는 `Yfacine/Yfacine` 프로필 README의 프로젝트 카드 생성, 수정, 개선, 이동과 배치에 적용한다. 작업 전에 현재 README와 인접 카드를 확인하고, 사용자의 명시적인 변경 요청이 있으면 그 요청을 우선한다. 카드 개별 이미지뿐 아니라 카드가 함께 놓인 실제 화면을 결과물로 취급한다.

## 시각적 방향

- [Asta-Profile의 04_흑백_만화풍](https://github.com/Yfacine/Asta-Profile/tree/main/04_%ED%9D%91%EB%B0%B1_%EB%A7%8C%ED%99%94%ED%92%8D)을 아스타와 잉크 선화의 스타일 기준으로 삼는다. 흑백 만화의 명암과 선화를 쓰고, 컬러·픽셀 아트·단순 아이콘 스타일로 임의 변경하지 않는다.
- 각 저장소의 주제 장면을 중심에 두고, 아스타가 오른쪽 아래에서 작게 그 장면을 바라보는 모습을 모든 카드와 표지에 공통으로 넣는다. MCP의 단체 그림과 Asta-Profile의 얼굴 그림에도 이 작은 안내자 구성을 적용한다. 캐릭터가 본래 주제나 글자를 가리지 않게 한다.
- 기존 프로필의 단정한 흑백 카드 구조와 텍스트 가독성을 유지한다. 이미지 생성으로 그림을 만들더라도 제목, 설명, 상태, 테두리와 바깥 여백은 공통 템플릿에서 정확하게 만든다.

## 기준 카드와 파일

- 공통 제작 소스는 `scripts/generate_cards.py`, 출력은 `assets/cards/v0.1/`과 `assets/covers/v0.1/`이다. 삽화 원본과 카드용 JPEG는 `assets/card-illustrations/v0.1/`에 보관한다. 카드 데이터와 템플릿을 소스에서 관리하고 저장소 루트에서 `python scripts/generate_cards.py`로 전체 카드와 표지를 재생성한다. 생성된 SVG를 직접 고치지 않는다.
- 프로필 소개 배너와 현황판은 `assets/presentation/v0.1/`에 보관한다.
- 기준 원본 캔버스는 **744 × 298 px**이다. 투명 여백을 포함한 크기이며, 내용의 가시 영역은 x=12~731, y=0~275이다. 좌우 각 12 px, 하단 22 px의 투명 여백이 배치 간격에 기여한다. 가시 영역과 여백은 캔버스 크기만큼 중요하다.
- 공통 템플릿은 가시 영역 x=12~731, y=0~275, 상태 띠 y=226~274를 사용한다. 새 카드는 동일한 캔버스, 투명 여백, 카드 테두리, 내부 정렬, 하단 상태 띠의 위치와 높이를 유지한다. 배경을 흰색이나 검정색으로 채워 투명 여백을 없애지 않는다. 글자나 이미지를 찌그러뜨리거나 잘라 맞추지 않는다.
- 재현 가능한 편집 소스와 삽화 원본을 보존한다. 생성 결과는 문구, 여백과 그림을 직접 확인한 후에 사용한다. 기존 카드를 변경할 때 요청과 무관한 내용, 문자, 그림과 배치를 임의로 바꾸지 않는다.
- 현재 main의 `assets`에는 v0.1 자료만 둔다. 이전 시안은 과거 Git 커밋에서 확인할 수 있으며 현재 프로필이나 새 표지의 기준으로 사용하지 않는다. 과거 커밋을 고정한 이미지 주소는 해당 커밋의 파일을 가리킨다.
- 2026-11-11 공개 접근 확인 시 OpenCraft와 Craft 재현 후보 10개 주소는 확인되지 않았다. 이는 비공개·이동·삭제 중 어느 사유인지 판단한 결과가 아니다. 공개가 확인되면 `UNLINKED`와 프로필 링크를 함께 갱신한다. `Craft-Vehicle Tracking`은 카드 표시명이며 저장소 이름 변경 완료를 의미하지 않는다.
- 모델 카드의 표시명은 `Craft-`와 현재 모델명으로 표기한다. 예: `Craft-FIRE`, `Craft-Vehicle Tracking`. 실제 GitHub 저장소명과 코드 식별자는 별도로 확인하며 표시명 변경만으로 바꾸지 않는다.
- 카드의 프로젝트명, 짧은 설명, 상태, 연결 대상과 대체 텍스트는 서로 일치해야 한다. 구현 전·구현 중 등 상태는 실제 사용자가 지정한 분류를 따른다. 확인되지 않은 기능이나 진행 상태를 만들어 적지 않는다.

## README 배치

- 같은 분류의 카드는 같은 `<p>` 안에 이미지로 연속 배치하고, 각 이미지에 `width="420"`을 적용한다. 공개 접근이 확인된 저장소만 이미지에 링크를 건다. 카드 사이에 빈 줄, 별도 문단, 강제 줄바꿈이나 임의의 공백 문자를 삽입하지 않는다. GitHub 렌더링 과정에서 빈 줄이 문단을 나눌 수 있다.
- 데스크톱에서 공간이 충분하면 2열로 나란히, 좁은 화면에서는 자연스럽게 1열로 줄바꿈한다. 카드 간 가로·세로 간격과 좌우 정렬은 기준 카드의 실제 표시를 따른다. 이미지 바깥의 투명 여백과 HTML 줄 간격을 함께 고려한다.
- 하나의 카드만 크기나 여백을 임의로 조정해 간격을 눈대중으로 보정하지 않는다. 분류 제목 아래 항목이 없으면 제목을 유지하고 내용을 비운다.
- 공개 링크가 확인되지 않는 카드는 링크 없이 `공개 주소 확인 중`으로 표시한다. 접근 가능 여부와 공개 상태는 변경될 수 있으므로 연결 전에 다시 확인한다. 공개 접근이 확인된 링크는 해당 저장소를 가리키고, `alt`는 프로젝트명과 설명 및 해당 상태를 담는다. 파일 교체 시 GitHub 이미지 캐시 때문에 이전 이미지가 보일 수 있으므로 실제 표시를 확인하고 필요한 경우 고정된 새 리비전을 사용한다.

## 완료 전 확인

1. 생성 스크립트를 실행한 뒤 생성 파일과 소스 데이터가 일치하는지 확인한다. SVG의 캔버스 크기, 가시 영역, 투명 여백 및 상태 문구를 비교한다.
2. GitHub가 렌더링한 프로필에서 변경 카드와 인접한 최소 두 행을 함께 보고, 각 열의 좌우 정렬과 카드 사이 가로·세로 간격이 다른 행과 같은지 확인한다. 첫 행만 확인하거나 이미지의 `width`만 비교해서 완료로 판단하지 않는다.
3. 데스크톱과 좁은 화면에서 줄바꿈, 잘림, 이미지 로딩 및 카드 순서를 확인한다. 실제 화면을 확인하지 못했다면 완료 보고에 그 한계를 명시한다.
4. 각 카드의 링크, 대체 텍스트, 이미지 내부 상태와 분류 제목이 일치하는지 확인한다. 범위 밖 콘텐츠는 보존한다.
